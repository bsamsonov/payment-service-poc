# 0006. Contract-first API with generated interfaces

- Status: Accepted
- Date: 2026-10-07

## Context and problem
The service exposes a REST API under `/api/v1` to internal clients. The contract must be reviewable before the code
exists (it is part of the spec), stay the single source of truth (`AGENTS.md`), and not drift from the implementation.
Spring Boot 4 uses Jackson 3, and our quality gates (Error Prone/NullAway, SpotBugs, Spotless, JaCoCo 80%) apply to
all compiled sources.

## Considered options
1. **Code-first**: write controllers and DTOs, publish the spec generated by springdoc.
2. **Contract-first, hand-written code**: write `api/openapi.yaml`, write DTOs by hand, check them against the
   contract with a contract test.
3. **Contract-first, generated interfaces**: write `api/openapi.yaml`, generate the API interface and DTOs with
   `openapi-generator-maven-plugin` (generator `spring`, `interfaceOnly`), controllers implement the interface.

## Decision
Option 3. The contract is written and reviewed first, and the compiler keeps the controllers in sync with it:
changing the contract without the code (or the reverse) breaks the build.

- Generator options: `interfaceOnly`, `useSpringBoot4`, `useJackson3`, `useBeanValidation`, `openApiNullable=false`,
  `skipDefaultInterface`, `useTags`. Output goes to `target/generated-sources` and is not committed.
- Generated packages (`adapter.in.web.api`, `adapter.in.web.model`) are used only by the web adapter (ArchUnit) and
  are excluded from Spotless, Error Prone/NullAway, SpotBugs and JaCoCo.
- Bean Validation from the schema covers only format checks (`400`). Business limits (amount range per currency) are
  not expressed as `minimum`/`maximum` in the schema: the generator would turn them into `@Min`/`@Max` and return `400`
  instead of `422`. They are documented in `description` and enforced in the domain.

## Consequences
- Positive: the API is designed and reviewed as a document; drift between contract and code is a compile error;
  client SDKs can be generated from the same file.
- Negative: a build-time dependency on the generator and its Boot 4 / Jackson 3 support, which is new; generated
  code style is not ours; some rules cannot be expressed in the schema and live in code.
- Fallback: if the generated code is unusable with Boot 4 / Jackson 3, switch to option 2 (hand-written DTOs plus a
  contract test) and record it in a new ADR.
